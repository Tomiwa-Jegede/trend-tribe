# Wayfinder Map — Referral Program Integration

## Destination
Referral program integration spec is locked and ready to hand off to build: DB schema + referral capture at signup + 5% commission engine (6-month window, idempotent, refund-reversible) crediting the existing wallet + user dashboard + admin visibility — all 10 decisions answered with smallest architectural delta, no open questions before implementation.

## Notes
- Domain: Trend Tribe marketplace referrals (Prisma/Postgres + Express + React/Tailwind + Flutterwave + Gig Wallet)
- Skills every session should consult: `product-brainstorming` for flow framing, `ui-ux-pro-max` for dashboard UX, `ponytail` for minimal integration
- Stack: `User {gigBalance, tokenBalance, gigAccountNumber}` + `TokenPurchase`/`GigTokenPurchase` (Flutterwave verify + webhook), `Gig`/`ServiceBooking` (escrow → GigWalletTransaction ledger), `PendingRegistration` (OTP), `Notification` + `push.js`/`realtime.js`
- Preferences: plan, don't do; produce decisions not deliverables; reuse existing wallet/ledger (`GigWalletTransaction` + `gigBalance`), auth, notification systems; configurable rate/duration in one place; every commission traceable Referrer → Referred → Transaction → Commission → Ledger; frontend never calculates money
- Tracker: local-markdown (`wayfinder/referral-program-map.md` + `wayfinder/tickets/referral-*.md`); labels `wayfinder:map` / `wayfinder:<type>` are header conventions inside each file

## Decisions so far
- [Referral Data Model](tickets/referral-01-data-model.md): 1 field on User (`referralCode @unique`) + 1 on PendingRegistration + new `Referral(referredId @unique, commissionEndAt)` + `ReferralCommission(@@unique[transactionType,transactionId])`; reuse `gigBalance` + `GigWalletTransaction`, no separate wallet.
- [Referral Code Generation Strategy](tickets/referral-02-code-generation.md): Default `A-Z0-9` 6-char auto-mint (`crypto.randomBytes`, `@@unique` guard) + **referrer can set his own code** via `PATCH /api/referrals/code {code}` (`4-12` A-Z0-9, upper-normalized, unique, reserved list, rate-limited); auto fallback if not set, change allowed (old links invalid, old referrals stay via FK) — *updated 2026-09-16 per user request*.
- [Transaction Eligibility — What Triggers 5%](tickets/referral-03-transaction-eligibility.md): V1 eligible = `GIG_TOPUP` (Gig `gt_` SUCCESS) + **`TOKEN` (Token `tt_` SUCCESS, Naira→kobo `*100`)** + `GIG COMPLETED` (claimer payout) + `SERVICE COMPLETED` (provider payout); all other statuses (FAILED/CANCELLED/EXPIRED/DISPUTED-debit/transfer/withdraw/`buyWithGigBalance`) not eligible or held; hook inside credit/confirm `$transaction` after ledger write, unit kobo with evidence — *updated 2026-09-16 to include TOKEN per user request*.
- [Config Centralization — Rate & Duration](tickets/referral-08-config.md): `config.referral.{rate:0.05,durationMonths:6}` in `backend/src/config/env.js:38` from `REFERRAL_COMMISSION_RATE`/`REFERRAL_DURATION_MONTHS` (validated 0-1 / 1-24), defaults keep existing deploys correct; no scattered `0.05`.
- [Idempotency & Duplicate Protection](tickets/referral-06-idempotency.md): `@@unique([transactionType,transactionId])` on `ReferralCommission` + `findUnique` inside same `$transaction` + `P2002` catch; discriminator `GIG_TOPUP/TOKEN/GIG/SERVICE` maps to `GigTokenPurchase.reference / TokenPurchase.reference / Gig.id / ServiceBooking.id` as String; inherits `creditGigPurchase`/`creditPurchase` `updateMany where PENDING` guard, webhook retry safe — *updated 2026-09-16 to include TOKEN*.
- [Referral Signup Capture Flow](tickets/referral-04-signup-capture.md): Frontend `?ref=` → `localStorage tt_referral` → `POST /register` + `POST /verify-registration` hidden field, persisted on `PendingRegistration.referralCode`; backend resolves code in `verifyRegistration` and creates `Referral` atomically with `User` (`$transaction`, `commissionEndAt = now + durationMonths`), self-referral 400, `referredId @unique` makes immutable.
- [Commission Engine & Wallet Credit](tickets/referral-05-commission-engine.md): Helper `maybeCreditReferral({referredId,type,id,amountKobo,tx})` inside each eligible `$transaction` (GIG_TOPUP `creditGigPurchase` after TOPUP, **`TOKEN` `creditPurchase` after tokenBalance increment with `*100` kobo conversion**, GIG `confirmGig`/`autoRelease` after GIG_PAYOUT, SERVICE `completeServiceBooking` after SERVICE_PAYOUT) credits `gigBalance` + `GigWalletTransaction REFERRAL_CREDIT` + `ReferralCommission` atomically; `gigBalance` reused, no new wallet; window check + rate snapshot from `config.referral` — *updated 2026-09-16 to include TOKEN*.
- [Refund, Reversal & Six-Month Expiry](tickets/referral-07-refund-reversal-expiry.md): `CREDITED→REVERSED` in same refund `$transaction` via `maybeReverseReferral` (only `COMPLETED/SUCCESS→REFUNDED` admin paths need it; cancel/expired before COMPLETED have no commission to reverse; TOKEN refunds never happen but `TOKEN` type included for completeness); window `commissionEndAt` query check + optional daily cron; clamp debit to 0 on insufficient referrer balance, track `debtKobo` in ledger meta.
- [User Referral Dashboard UX](tickets/referral-09-dashboard.md): Protected `/referrals` page `ReferralPage.jsx` (lazy, `Navbar` link, Tailwind `ProfilePage`/`GigWalletPage` cards), shows code/link + Copy/Share + **Edit custom code** (`PATCH /api/referrals/code`), stats (total/active/expired/total/available), per-referral `commissionEndAt` countdown + ACTIVE/EXPIRED badge, paginated earnings history (`GET /api/referrals/me` + `/commissions`); `Framer Motion` + `usePageviewTracking`, no new visual system — *updated 2026-09-16 to include custom code edit*.
- [Admin Visibility, Notifications & Abuse Guards](tickets/referral-10-admin-notifications.md): Admin `GET /api/admin/referrals/*` stats + referral list + commission history reusing `admin.middleware` + `AdminRoute`, indexes on referrals/commissions; notifications `REFERRAL_NEW_USER` on `Referral` create + `REFERRAL_CREDIT` on commission via `Notification`/`push.js`/`realtime.js` (no expiry push for V1); all abuse guards via `referredId @unique`, `@@unique([transactionType,transactionId])`, `authLimiter`, eligible-set filter, webhook idempotency, `P2002` retry.

## Out of scope
- Multi-level / tiered referrals (only direct referrer for V1)
- Separate referral wallet — intentionally reused existing `gigBalance` + `GigWalletTransaction` unless schema ticket proves otherwise
- Changing referral after account creation or self-referral (explicitly prevented)
- Rebuilding existing transaction flows — commissions hook into existing flows, not replace them
